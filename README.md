# Nezha Domain Management

这是一个基于 [Nezha](https://github.com/naiba/nezha) 开发的定制版本，集成了域名管理等扩展功能。项目采用了前后端分离的架构，并通过 Git Submodules 管理各个组件。

## 项目结构

- **`admin-frontend-domain`**: 管理员后台前端界面。
- **`nezha-dash-v1`**: 用户前台面板/仪表盘。
- **`nezha_domains`**: 项目的核心后端服务（Go 编写）。
- **`build.sh`**: 一键构建脚本，负责同步子模块、编译前后端并生成最终的可执行文件。

## 环境要求

在开始构建之前，请确保您的系统中已安装以下工具：

- **Git**: 用于克隆仓库及管理子模块。
- **Node.js 22.22.2+（或 24 LTS）与 pnpm 11+**: 用于编译前端项目。
- **Go 1.26.10+ 与 C 编译器**: 后端使用 CGO SQLite；请勿使用存在 HTTP/2 长连接超时缺陷的 Go 1.26.6。
- **Swag**: 用于生成 Swagger 接口文档（构建脚本会自动尝试安装）。

## 构建指南

项目提供了一个完整的构建脚本 `build.sh`，可以自动化执行所有构建步骤：

```bash
# 给脚本添加执行权限
chmod +x build.sh

# 运行构建脚本
./build.sh
```

### 脚本执行流程：
1. **更新子模块**: 初始化 Git Submodules 到父仓库记录的版本（不会自动合并上游最新功能）。
2. **编译管理员前端**: 进入 `admin-frontend-domain` 目录，安装依赖并打包。
3. **编译用户前端**: 进入 `nezha-dash-v1` 目录，安装依赖并打包。
4. **同步产物**: 将前端打包生成的静态文件拷贝至后端指定的目录。
5. **编译后端**: 生成 Swagger 文档并编译 Go 代码，最终在根目录下生成 `nezha-server` 可执行文件。

## 运行

构建完成后，直接运行生成的二进制文件即可：

```bash
./nezha-server
```

## 注意事项

- **大文件限制**: 本项目已移除历史提交中的大型二进制文件。请避免将编译生成的 `nezha-server` 提交到 Git 仓库中。
- **子模块同步**: 如果手动修改了子模块代码，请确保在子模块目录内完成提交和推送。
